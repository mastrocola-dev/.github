# mastrocola.dev

> Event-driven systems, done right. A living portfolio built as a real company.

**[mastrocola.dev](https://mastrocola.dev)** is a software engineering organization built from scratch to demonstrate — in public — how to design, build, and operate mission-critical backend platforms. Every architectural decision is documented, every service is production-grade, and everything runs on real cloud infrastructure.

Created and maintained by [Marcio Mastrocola Alcantara](https://www.linkedin.com/in/marcio-mastrocola) — Software Architect specialized in modernizing legacy systems, event-driven architectures, and data engineering.

## Why this exists

Most portfolios are a pile of tutorial clones. This one is structured like an actual company:

- **Multi-repo architecture** with clear domain boundaries
- **Infrastructure as Code** provisioning real Azure resources via OIDC-authenticated pipelines
- **Documented decisions** — every significant choice has an ADR explaining the trade-offs
- **Production practices** — CI/CD, observability, and automated testing from day one

Even the landing page follows the rules: [mastrocola.dev](https://mastrocola.dev) is served by Azure Static Web Apps declared in Terraform, with its DNS zone managed as code and deployed by its own pipeline — the site is itself a working sample of the platform. It also answers for itself: visitors can ask how it is built, and an AI agent replies from the architecture documentation, citing the records it used ([how that runs](https://github.com/mastrocola-dev/docs/blob/main/architecture/agent-runtime.md)).

The goal is twofold: showcase architectural competence, and keep the door open for this to become a real product company.

## Tech stack

**Backend:** Node.js (TypeScript), Python
**Architecture:** Event-driven microservices
**Cloud:** Microsoft Azure (Functions, Service Bus, Table Storage, Key Vault, Static Web Apps), Cloudflare, Terraform, GitHub Actions with OIDC federation
**AI:** Anthropic API, Model Context Protocol
**Data & messaging:** SQL Server, PostgreSQL, MongoDB, RabbitMQ, Apache Airflow
**Observability:** Grafana, Elasticsearch/Kibana

## Roadmap

- [x] Base infrastructure on Azure (`infra`)
- [x] Multi-repo structure with organization-wide OIDC authentication
- [x] Documentation baseline: ADRs and operational runbooks (`docs`)
- [x] Public site live at [mastrocola.dev](https://mastrocola.dev) — hosting, DNS and deploys fully as code
- [x] Landing page content and design
- [x] Agent architecture decided — host language, LLM integration, RAG deferred ([ADR-003](https://github.com/mastrocola-dev/docs/blob/main/adr/003-language-llm-rag.md))
- [x] Agent MVP: CLI host, first MCP server, guardrails, structured output and traces (`service-agent`, `mcp-docs`)
- [x] Agent in the pipeline: the site's decision index is generated by the agent and reviewed in the pull request ([ADR-005](https://github.com/mastrocola-dev/docs/blob/main/adr/005-agent-generated-content.md))
- [x] Zero secrets in GitHub: one identity per repository, Key Vault as the only store ([ADR-006](https://github.com/mastrocola-dev/docs/blob/main/adr/006-identity-and-secrets.md))
- [x] Agent runtime in production: visitors ask the site how it works; queue-based jobs on serverless functions, behind an edge with rate limiting, quotas and a daily budget ([ADR-007](https://github.com/mastrocola-dev/docs/blob/main/adr/007-agent-runtime.md))
- [ ] A real site in React with a backend-for-frontend, and the services behind it made private
- [ ] Security baseline with a written threat model
- [ ] Conversation memory and real-time progress for the agent
- [ ] C4 architecture diagrams (`docs`)
- [ ] `template-service` with golden-path CI/CD
- [ ] First domain service end-to-end (API → event bus → persistence)
- [ ] Observability wired to all services
